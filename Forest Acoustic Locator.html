Forest Acoustic Locator

GPS in reverse. Satellites at known positions let your phone find itself from signal delays. Here, microphone nodes at known positions in a forest find a sound from its delays: a gunshot, a chainsaw, or the call of a rare animal.

1 ms = 34 cmEach millisecond of timing error moves the answer about a third of a metre.
3 nodes minimumThree fix a position on the map. Four or more remove ambiguity and average out noise.

How the system works

STEP 1 · LISTEN

Nodes hear the sound

Each node samples a MEMS microphone at 16 kHz. A cheap detector runs all the time: a loudness spike for gunshots, a small neural network on the spectrogram for animal calls.

STEP 2 · TIME-STAMP

Record exact arrival time

A GPS receiver gives every node the same clock through its 1-pulse-per-second signal. The nRF52840 timer captures that pulse, so the sound's arrival is timed to about 0.1 ms.

STEP 3 · REPORT

Send a tiny packet

Only about 16 bytes leave the node: ID, timestamp, loudness, class and confidence. A long-range radio carries it to a gateway. No audio is streamed, so batteries last.

STEP 4 · SOLVE

Gateway computes the location

Reports that arrive within a few seconds of each other are grouped. The solver finds the point whose distances to the nodes fit the timing differences, then sends an alert with coordinates.

The maths behind the map

The sound leaves an unknown place at an unknown moment. Every node knows only when it heard the sound. Subtracting one arrival time from another cancels the unknown moment and leaves a pure distance difference.

One pair of nodes gives a hyperbola: every point whose distances to the two nodes differ by that amount. A second pair gives a second curve. The sound is where they cross, which is what the coloured curves in the simulator show.

With exactly three nodes the curves can cross twice, so the answer is sometimes ambiguous (the simulator shows a dashed ghost when this happens). A fourth node settles it, and more nodes let the solver average out timing noise.

di = | p − ni |
Distance from the unknown source p to node i at known position ni.
ti = t0 + di / c
Node i hears the sound after the unknown emission time t0 plus the travel time.
di − dj = c · (ti − tj)
Subtract two nodes: t0 disappears and one hyperbola remains.
c ≈ 331.3 + 0.606 · T°C m/s
Each node carries a temperature sensor, because a 6 °C error in air temperature shifts c by about 1% and the whole map with it.

What goes in each node

MCU
nRF52840 (Cortex-M4F, 64 MHz). Has a PDM microphone interface, 16 MHz timers with hardware capture (PPI), and a very low-power sleep mode.
Microphone
PDM MEMS microphone with a high acoustic overload point so a close gunshot does not clip, under a foam windscreen.
Clock + position
u-blox GNSS module with a PPS output. It gives the node's own coordinates and a shared time base across the whole forest.
Radio
LoRa transceiver (SX126x) on SPI for kilometre links. The nRF52840's own BLE or Thread radio can cover short hops or setup over a phone.
Environment
Temperature and humidity sensor (BME280 class) for the speed-of-sound correction.
Power
Li-ion cell with a small solar panel, in an IP65 box with a mesh-covered microphone port.
Gateway
One LoRa receiver with a Raspberry Pi or ESP32, running the solver and sending alerts by mobile data or satellite link.

The report packet is small enough to send in one LoRa frame:

struct EventReport {      // ~16 bytes
  uint8_t  node_id;
  uint32_t gps_second;    // UTC second from GNSS
  uint32_t ticks_16mhz;   // timer count inside that second
  uint8_t  sound_class;   // gunshot, chainsaw, call #n
  uint8_t  confidence;    // 0-255
  int16_t  peak_dbfs_x10; // loudness
  int16_t  temp_c_x10;    // for speed of sound
};

A gunshot has a sharp start, so each node can time it from the first rise in loudness. An animal call fades in gradually, so the first rise is unclear. For calls, nodes send a short audio snippet or spectrogram on request, and the gateway lines the snippets up by cross-correlation (GCC-PHAT). Try the "Animal call" setting in the simulator to see what that larger timing error does.

What can go wrong, and the plan for it

Clock agreement

Nodes must share time to well under a millisecond. GPS PPS solves this. If a node loses its fix, it can resync from a neighbour's beacon.

Temperature and wind

Air temperature changes c; wind pushes sound along. Temperature sensors correct the first; more nodes than the minimum average the second.

Echoes in dense forest

Sound bounces off trunks and hillsides. The solver uses only the first arrival and the classifier rejects clips with several similar peaks.

Range and foliage

Gunshots carry kilometres; quiet animal calls maybe a few hundred metres. Node spacing should follow the quietest sound you care about.

Poor geometry

Sounds inside the area covered by the nodes locate best. Outside, small timing errors stretch into large position errors, as the simulator shows when you click near an edge.

False alarms

Thunder and falling branches sound like gunshots. Require two or more nodes to agree on class and arrival times before raising an alert.

Build plan

Phase 1

Bench and open field. Three nodes on a football pitch at surveyed points. Play a loud click from a speaker at known spots and compare computed with real positions. This gives the real accuracy numbers.

Phase 2

Detector. Record gunshot-like sounds (or recordings), chainsaws, rain, wind and target animal calls. Train a small classifier that fits on the nRF52840.

Phase 3

Radio and gateway. Add LoRa reports, the gateway solver and a map dashboard with alerts.

Phase 4

Forest trial. Solar power, weatherproofing and a few weeks in the field. Measure battery life, false alarms and range.

Phase 5

Scale up. Add nodes to widen the area. The same solver handles any number of nodes.

The simulator uses a made-up 2 km square, a fixed speed of sound of 343 m/s and Gaussian timing noise. Accuracy in a real forest depends on echoes, wind and node layout, and Phase 1 is where those numbers get measured.
